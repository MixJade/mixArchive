## 一、风水大吉

游戏中的风水遵循【五行相生】的规则。

### 1.1 家具的两类标签

- **风水建筑**：带有【风水建筑】标签的家具（如床），这类家具需要满足五行相生才能达到大吉。
- **普通家具**：没有【风水建筑】标签的家具（如灯、风物旗），这类家具没有凶吉概念，无需理会，一般用来调节【风水建筑】所在格的元素浓度。

### 1.2 如何让风水建筑大吉

让【普通家具】来"生"【风水建筑】即可。例如床是金属性，在旁边放一个土属性的灯，就能满足【土生金】。

> **关键点**：放土属性灯的作用，主要是提高所在格周围的土元素浓度。风水建筑的大吉与否，取决于它所在格的元素浓度。因此，放金属性床的房间通常搭配土墙、土地板。（墙一般只影响相邻一格，所以靠墙的建筑可以省一些装饰物。）

### 1.3 特殊家具

- **置物台**：标签为【无】，即无论用什么材料都不影响周围元素浓度。通常用寒精或火精制作置物台，用来调节房间温度。

### 1.4 灵气场与地块

- 部分物品带有灵气场属性，在【风水】视角下点击材料（或者建筑）时，会看到一圈光晕，这个光晕范围内对应的元素浓度会上升。
- 地块同样影响元素浓度：浅水地块水元素多、土地地块土元素多、岩石地皮金元素多。

### 1.5 房间大吉条件

上述是【风水建筑】的大吉条件；房间的大吉条件相对简单，只需各项评分相加超过 14 分即可：

1. **建筑吉利**：房间内所有【风水建筑】均为大吉（大吉 8 分、吉 6 分，取房间内所有风水建筑分的平均值）。
2. **朝向正确**：根据房间内【风水建筑】确定房间朝向（门朝哪开、且只能有一个门）。例如【灶台】门朝西、【铁匠铺】【磨坊】【熔炉】门朝东、【床】【祖师牌位】门朝南（具体朝向可建一个专用测试房间来验证）（朝向正确 3 分）。
3. **家具密度**：密度处于合适区间（不过于拥挤也不过于空旷），加 3 分。

此外，也可用【通灵镇物】来调整房间大吉：满足【通灵镇物】条件则房间大吉（加 30 分），反之大凶（减 30 分）。

## 二、关于阵法

阵法中只有【阵枢】在输出，其余位置都相当于"充电宝"。

因此尽量让输出位站阵枢，防御位站阵眼。

## 三、不要点【天道神器】

【天道神器】会把炼器速度锁定为 -50%，相当于此前学习的一堆加炼器速度的秘籍全部失效。（也有说法称【天道神器】本质是 -1000% 炼器速度，这个 -50% 其实是炼器速度的下限。）

## 四、批量取消禁用

如果屏幕中有太多同类物品被禁用（比如粪便），那么双击其中一个就能选中所有同类物品，然后取消禁用即可。

也有另一种快捷键：按住Ctrl，再拖动取消，就是把范围内所有物品禁用/取消禁用

## 六、灵气场与聚灵

首先要区分两个概念：**聚灵 ≠ 灵气场**。

**灵气场**：在【风水】视角下点击材料时，会看到一圈光晕，这就是灵气场。处于该气场范围内的地块，对应五行的灵气比例会被调控（例如【凶凤的蔽天羽】会提高周围两格的火灵气比例）。气场的覆盖范围只能通过材料周围的光晕来判断。

**聚灵**：聚灵不是“灵气”，而是在地块上铺一层**聚灵势场**（`g_emMapEffectKind.LingAddion`）。它在计算灵气差时，把自己这格的势能**扣掉**一个聚灵值——注意是只在算式里扣，真实灵气 `Value` 一点不动：

1. 作为**收货方**：扣得越多，自己显得越“空”，上游看它的落差越大，于是灌得越快；
2. 作为**发货方**：扣得越多，越难把灵气放出去；扣到灵气不够扣（`num2 < 1`）时，干脆停止外放（见 6.4）。

它本身**不产出任何灵气**，也与五行属性无关。（例如【凶凤的蔽天羽】“聚灵 35、范围 5”，是在其周围 4 格（实际覆盖半径 = 范围 − 1）内铺上 35 点聚灵势。）

> **常见误解**：“这份额外容量不参与灵气扩散的计算。”实际恰好相反：扩散的判定基准**就是**这个值。所谓“额外灵气容量”，本质就是“稳态下该格能比周围多存下这么多灵气”——它正是靠在差值里扣除来实现的（见 6.4）。

聚灵值本身会在 5 天内爬满：`GetEffect(..., checktime: true)` 会再乘 `Mathf.Lerp(0, 1, (TolSecond − CreateTime) / 3000)`，即 3000 游戏秒（= 5 天）内从 0 线性升到 100%。这个 5 天是**成型时间**，不是“收菜周期”（见 6.7）。

### 6.1 聚灵参数

> 聚灵物的属性释义

```xml
<Ling>
	<AddionLing>1200</AddionLing>  <!-- 聚灵强度 -->
	<AddionRadius>5</AddionRadius>  <!-- 聚灵范围：实际覆盖 中心 + (N−1) 环-->
	<AddionFailing>0.95</AddionFailing> <!-- 聚灵衰减速度：超出开始衰减半径后每环乘一次 -->
	<AddionFailRadius>4</AddionFailRadius> <!-- 开始衰减半径：这个距离以内满强度，实际覆盖N环 -->
</Ling>
```

### 6.2 气场参数

```xml
<Element>
    <Kind>None</Kind>      <!-- 保持哨兵 → 种类仍随建造材料 -->
    <Value>20</Value>      <!-- 气场强度 -->
    <Radius>5</Radius>     <!-- 气场范围：实际覆盖 中心 + (N−1) 环 -->
    <Failing>0.9</Failing> <!-- 气场衰减范围：超出满强度区后每环乘一次 -->
    <FailRadius>2</FailRadius> <!-- 开始衰减半径：实际覆盖N环 -->
</Element>
```

### 6.3 聚灵和灵气是两个独立数值

| | 聚灵 | 灵气 |
|---|---|---|
| 代码字段 | `LingAddion`（空间势场） | `LingMapData.LQData.Value` |
| 来源 | `Thing.SetLing()` → `AddEffectSource(...)` | 灵脉 `<LingSource>` + 相邻地块扩散 |
| 作用 | 只在算差值时扣除，**不改动 `Value`** | 修士打坐实际吸取的量 |
| 稳态关系 | `V自 = V邻 + 聚灵`（这就是“额外容量”） | 受 2500 附近的衰减压制 |

### 6.4 灵气每轮怎么演化（`LingMapData.UpdateLingUnit`）

```csharp
// 1. 先衰减
if (V < 2500)  V = Mathf.Min(V - 0.1f, V * 0.99f);
else           V = 0.99f * Mathf.Pow(V / 2500f, -0.8239f) * V;   // 超过 2500 后掉得极快

// 2. 判定（这一行决定了“聚灵”真正的含义）
num2 = V - Mathf.Max(0f, 聚灵);
if (num2 < 1f) return;          // 整格直接退出，一个邻居都不通知

// 3. 只向势能更低的相邻格输送
num4 = 邻居V - 邻居聚灵;
if (num4 >= num2) continue;
num6 = num2 - num4;             // 差值 < 0.4 不动；>= 15.6 时按 diff / 1.3 搬
```

聚灵在这个式子里出现**两次，方向相反**，这就是它的全部作用：

| 身份 | 用到的量 | 聚灵变大时会怎样 |
|---|---|---|
| 收货方 | `num4 = V − 聚灵` | 显得更低 → 上游算出的落差 `num6` 变大 → 搬运量 `num5` 变大 → **回填更快** |
| 发货方 | `num2 = V − 聚灵` | 显得更低 → 外放变少；`num2 < 1` 时**完全停止外放** |

所以“在计算灵气差时把这个值扣掉，用增大的差值变相提高回灵速度”这个说法是准确的：聚灵并不创造灵气，它把自己的势能水位打折，让别人看自己更“空”，从而以更大的落差从上游抽取。而官方所说的“增加额外灵气容量”是同一件事的另一种表述——稳态时上下游的净值相等：

```
num2自 = num2邻  →  V自 − 聚灵 = V邻  →  V自 = V邻 + 聚灵
```

即**该格最终能比周围多存下“聚灵”这么多灵气**，这才是“容量”的来源。

> 三个容易搞反的地方：
> - **`num2 < 1` 只挡发货，不挡收货。** 聚灵过高的格子不是“进不来”，而是“出不去”——它对上游的落差极大，是全场收货最猛的一格，属于**只进不出的终端**。
> - **发货方的 `Value` 不被扣。** 循环里只有收货方的值被改写，扩散本质是“按势差凭空生成”，不是搬水。所以聚灵抽得再狠，也不会让上游变穷。
> - **修士和法宝的吸收只看真实灵气。** `num12 = max(V × 五行系数 / 40, 0) × LingAbsorbSpeed × 4`，这里的 `V` 就是 `lQData.Value`。聚灵对吸收速度没有直接加成，只能通过抬高 `V` 间接生效。

### 6.5 单格聚灵不要超过 2500

灵气自身有稳态上限：低于 2500 时每轮只掉 1%（外加固定 −0.1），**超过 2500 后衰减变成 `(V/2500)^-0.82` 的超线性形式**，实际稳态大致被压在 2000~3000。

按 6.4 的稳态式 `V自 = V邻 + 聚灵`，看上去聚灵越高存得越多，但有两个反向因素把它顶回来：

1. **衰减**：`V` 一旦越过 2500，衰减量暴涨，聚灵抬上去的那部分会被迅速吃掉，堆到 2500 以上基本是白堆。
2. **链条中断**：灵气是逐格“发货”传出去的，而发货要求 `num2 >= 1`。当聚灵接近或超过该格的实际灵气时，它就不再有资格发货，扩散链条在这一格停下。

| 单格聚灵 | 结果 |
|---|---|
| < 2000 | 正常。灵气能超过聚灵，该格既能收也能往外放，灵气可以穿过去 |
| ≈ 2500 | 临界。勉强够到判据，吞吐很吃力，链条时通时断 |
| > 2500 | `num2 < 1` → 只进不出，成为终点站，灵气无法穿过这一层 |

而聚灵是**叠加**的：多个聚灵物的范围重叠时，单格会把所有贡献相加。`AddionFailing = 1`（不随距离衰减）时，一个物品就把 N×N 整片铺满，几个叠在一起单格就很容易越过 2500。

一旦一整圈都是终点站，这一圈就把灵气截断在内外两侧：圈内只剩自己那份残留的灵气，而它每轮都在衰减，**导致圈内最终灵气会为 0**

### 6.6 小技巧：中心灵气不足，拆一个聚灵物

用的是 5 天成型机制。`creattime` 是**按格**记录的，而 `GetEffect(..., checktime: true)` 会把该格所有聚灵源的**总和**再乘一个爬升系数：

```
系数 = Mathf.Lerp(0, 1, (TolSecond − creattime) / 3000)
```

所以只要让某一格的 `creattime` 刷新成“现在”，这一格的聚灵总值（包括其它所有聚灵物贡献的部分）就会整体从 0 重新爬 5 天。触发方式：**拆掉一个聚灵物再摆回去**（建筑重新建造、物品拿起再放下都行）。

- 这 5 天里，被它覆盖的那片格子聚灵接近 0，不再是只进不出的终点站，灵气可以重新穿过；
- 被挡在阵外的灵气会顺着势差涌进来，阵内原本憋住的灵气也会往外散，两边都会动；
- 5 天后再爬满、重新封住，所以这是**临时通气**，不是永久修复。

> 注意：单纯拆掉只是减掉那一份聚灵，不会重置计时；要拆了再摆回去（刷新 `creattime`）才触发。

### 6.7 常见误区：五天是“成型”，不是“收菜”

- 5 天 = 3000 游戏秒，只是**聚灵值从 0 线性爬到 100%** 的时间，作用对象是聚灵，不是灵气。
- 灵气被吸走后的回填速度由扩散决定：每轮按落差的 `1 / 1.3` 补入（发货方不扣灵气，等于净增），一轮结算就基本补回来了，跟 5 天没有任何关系。
- 所以不存在“每五天收一次菜”这种周期。真正以 5 天为周期的只有一件事：**拆建聚灵物后的重新成型**。

## 七、法宝回灵速度的误区

网上常见“回灵速度越快越好”的说法，其实并不准确。法宝最关键的属性是**威力**，而不是“回灵速度大于灵气容量”。

所谓回灵速度，指的是**法宝每秒从角色身上吸取的灵气量**。它需要与法宝的灵气容量相互匹配：一旦每秒吸取量超过了容量，相当于白白抽取了角色的灵气，纯属浪费。
